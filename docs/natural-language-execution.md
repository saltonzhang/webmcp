# 自然语言执行规范

## 两种使用方式

项目同时支持两种方式，它们使用同一个 WebMCP 工具层：

| 方式 | 适合什么 | 入口 |
| --- | --- | --- |
| 自然语言执行 | 临时业务操作、探索和定位问题 | 直接向 AI 描述目标 |
| JSON 回归用例 | 稳定、重复执行的验证 | `npm test` 或 `npm run test:case` |

自然语言不是让 AI 模拟鼠标点击，而是让 AI 将意图映射为当前页面实际注册的 WebMCP 工具调用。

## AI 必须执行的流程

1. 确认用户指定或当前使用的环境，并验证浏览器页面 origin 与环境配置相符。
2. 查询当前页面的 WebMCP 工具定义；页面没有注册所需工具时，明确说明阻断，不猜测 UI 操作。
3. 先调用只读工具，找出用户所说的市场、订单、余额或状态。
4. 将自然语言参数映射为业务 ID 后调用工具；每个改变状态的步骤后重新读取结构化状态。
5. 最终影响资金或订单状态的动作前，展示最终数据并等待确认。
6. 输出简短的执行结果与证据；可重复的探索建议沉淀为 JSON 用例。

## 同事可直接使用的表达

简短表达已经足够：

```text
在 test1 找 Flamengo vs Palmeiras 的 Flamengo 胜，赔率必须为 2.10，下注单设置为 100，但先不要提交。
```

AI 应执行：查询市场 → 校验 m1/赔率/可用状态 → 加入选项 → 设置 100 → `get_slip` 核验，而不是按页面位置点选。

需要提交时，用户再说：

```text
确认提交刚才这张单。
```

AI 必须在提交前再次显示环境、选项、当前赔率、下注额、预计派彩和余额影响。

## 更复杂的探索示例

```text
在 dev 验证串关赔率变化：选择三场不同比赛，各下注 25，应用满足条件的串关优惠；
模拟其中一场赔率变化，确认未接受新赔率时提交会被拦截。不要提交接受新赔率后的最终订单。
```

此类请求不必先写 JSON。AI 应先发现 dev 当前页面可用的工具，按工具定义执行，并保存结构化结果。确认该场景需要长期回归后，再写成 JSON 用例。

## 边界

- 环境、账号、赔率、市场或工具不明确时，先查询或提问，不替换为“最接近”的值。
- 生产环境、真实资金或非测试账户不得执行状态变更。
- `place_bet`、撤单、Cashout、结算和钱包变动一律需要提交前的明确确认。
